本文档面向现场运维人员，说明如何在 Windows 10/11 上通过 deploy/run/ 启动包人工部署与日常维护 PostgreSQL、MinIO、NanoMQ、Nginx 四个基础设施组件。

本目录提供便携脚本（config.ini + .bat），与 Linux 侧 scripts/service-*.sh 行为对齐。本文不包含 tenant-api / tenant-web 的构建与打包，仅说明上述组件与后端的对接参数。

端口一览

组件默认端口说明
PostgreSQL5432应用库 freetv_edge（EDGE）、freetv_cloud（CLOUD）
MinIO API9000S3 API，listen_bind 默认 127.0.0.1
MinIO Console9001Web 管理控制台
NanoMQ MQTT1883设备/Hub TCP 连接
NanoMQ HTTP8082本机运维 REST（仅 127.0.0.1）
NanoMQ WebSocket8083WS 监听（nginx 可代理为 WSS :8084）
Nginx HTTP80跳转至 HTTPS :8081
Nginx 租户入口8081HTTPS：Web + API + /files/ + MinIO 路径前缀
Nginx MinIO API9002独立 HTTPS 反代至 MinIO :9000
Nginx MinIO Console9003独立 HTTPS 反代至 MinIO :9001
Nginx MQTTS8883四层 TLS 代理至 NanoMQ :1883
Nginx WSS8084四层 TLS 代理至 NanoMQ WS :8083
Nginx 平台后台8080HTTPS 反代 platform-api（可选）
tenant-api（上游）8443需另行启动，非本目录脚本
tenant-web（上游）2001需另行启动，nginx tenant.conf upstream

端口可在各组件 config.ini 或 nginx conf/proxy/*.conf 中修改；修改后须同步 tenant-api 配置与防火墙规则。

依赖与启动顺序

PostgreSQL → tenant-api → NanoMQ │ MinIO → Nginx ← tenant-web
要点：
  1. PostgreSQL 须最先就绪；tenant-api 依赖数据库 DSN。
  2. NanoMQ 通过 HTTP 回调 tenant-api 完成 MQTT 认证；start-nanomq.bat 默认探测 http://127.0.0.1:8443/api/v1/health。
  3. Nginx 反代 MinIO（:9000/:9001）及 tenant-api（:8443）、tenant-web（:2001）。
  4. 勿同时将 EMQX 与 NanoMQ 作为 Hub 目标。

推荐启动顺序

顺序组件命令
1PostgreSQLpostgresql\start-postgres.bat
2初始化库postgresql\init-db.bat tenant --schema

首次部署 Checklist

1. 准备二进制与证书

组件操作
PostgreSQL安装 PostgreSQL 16+，或 run_mode=pg_ctl 并将二进制放入 postgresql/bin/
MinIO将 minio.exe、mc.exe 放入 minio/（可自动下载 minio）
NanoMQ从 nanomq.io/downloads 解压到 nanomq/bin/
Nginx确认 nginx.exe；TLS 证书放入 nginx/conf/ssl/

2. 编辑 config.ini

使用生产密码，勿将示例占位符用于上线环境。

PostgreSQL 示例

[PostgreSQL]
install_path = C:\Program Files\PostgreSQL\16
port = 5432
listen_bind = 127.0.0.1
run_mode = service

[Application]
user = freetv
password = changeme
db_edge = freetv_edge
db_cloud = freetv_cloud

MinIO 示例

[MinIO]
api_port = 9000
console_port = 9001
listen_bind = 127.0.0.1
bucket = freetv-assets

[Credentials]
root_user = ycwlminio
root_password = changeme

NanoMQ 示例

[NanoMQ]
mqtt_port = 1883
http_port = 8082
ws_port = 8083

[TenantAPI]
base_url = http://127.0.0.1:8443
check_health_before_start = true

3. 以管理员运行启动脚本

首次启动会添加 Windows 防火墙入站规则。右键「以管理员身份运行」或由脚本自动提权。

4. 按顺序启动并初始化

deploy\run\postgresql\start-postgres.bat
deploy\run\postgresql\init-db.bat tenant --schema
deploy\run\minio\start-minio.bat
deploy\run\minio\minio-mc.bat
REM 启动 tenant-api、tenant-web 后：
deploy\run\nanomq\start-nanomq.bat
deploy\run\nginx\start-nginx.bat

start-minio.bat、start-postgres.bat 会保持窗口打开；关闭窗口即停止进程。

5. 验证

组件验证方式
PostgreSQLstatus-postgres.bat；psql-client.bat
MinIOstatus-minio.bat；浏览器 http://127.0.0.1:9001
NanoMQMQTT 客户端连 tcp://127.0.0.1:1883
Nginxhttps://127.0.0.1:8081/
tenant-apicurl http://127.0.0.1:8443/api/v1/health

安全与生产建议

  1. 修改所有默认密码：PostgreSQL 应用用户、MinIO root、Hub gouser、YCWL_JWT_SECRET。
  2. 监听地址：默认 127.0.0.1；局域网访问改 listen_bind=0.0.0.0 并限制防火墙。
  3. TLS：替换开发证书；设备 MQTTS 使用正式 CA。
  4. 对外 URL 一致：SERVER_PUBLIC_URL、YCWL_NGINX_PUBLIC_URL 与 nginx 实际地址一致。
  5. 数据备份：定期备份 postgresql/data、minio/data、License 与配置。
  6. 管理员权限：MinIO 窗口模式勿误关窗口导致服务停止。
